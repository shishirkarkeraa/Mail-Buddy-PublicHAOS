MAIL-BUDDY: START AND GMAIL CONNECTION GUIDE
=============================================
Use this file for the complete supported deployment on:
  A. macOS with Docker Desktop, accessible only from that Mac
  B. Raspberry Pi OS 64-bit with Docker Engine, accessible on a private LAN

Run project commands from the directory containing compose.yaml.

Mail-Buddy uses local SQLite and local Ollama. It does not need DATABASE_URL,
PostgreSQL, MySQL, Redis, an OpenAI key, Gmail password, Gmail app password,
SMTP, hosted AI, or a paid service.

Safety:
  - Connect a dedicated Gmail test account first.
  - Never configure router port forwarding for this project.
  - Never put passwords, keys, or OAuth JSON in .env.
  - Never run "docker compose down -v"; "-v" deletes local volumes.
  - Historical scanning does not change Gmail until a category is approved.
  - Every Mail-Buddy-labeled message, including Needs Review, is removed from INBOX.
  - General and shopping promotions are moved to Gmail Trash, not permanently deleted.

Cost and license boundary:
  - Mail-Buddy makes no hosted-model calls and uses no paid database.
  - Docker Desktop is free for personal use under its current license:
      https://docs.docker.com/subscription/desktop-license/
  - Standard Gmail API use is currently free below Google's daily quota
    threshold. Google has announced future charges only for usage beyond that
    threshold. This single-account app is designed for ordinary personal usage
    and never requests a quota increase. For a strictly no-charge deployment,
    use a separate Google Cloud project without a billing account and review:
      https://developers.google.com/workspace/gmail/api/reference/quota
  - Llama 3.2 is local but remains subject to the Meta Llama Community License.


1. INSTALL THE PLATFORM REQUIREMENTS
====================================
macOS
-----
Install and start current Docker Desktop:
  https://docs.docker.com/desktop/setup/install/mac-install/

Give the Docker VM at least 6 GB memory and 4 CPUs. Use 7-8 GB when the Mac has
16 GB or more physical memory. On an 8 GB Mac, close competing workloads and
expect slower inference. The current Ollama container is limited to 5 GB.

Check:
  docker version
  docker compose version
  uname -m
  df -h .

Apple Silicon and Intel Macs select their native Linux image variant. Ollama
runs inside Docker's Linux VM; treat it as CPU inference and do not expect
Apple Metal acceleration. Keep at least 10 GB free. Ports 443 and 8765 must be
available.

Raspberry Pi
------------
Use a Raspberry Pi 5 with 8 GB RAM, active cooling, 64-bit Raspberry Pi OS, a
fixed private IPv4 address, and at least 10 GB free.
  uname -m
  getconf LONG_BIT
  df -h /

Expected architecture is aarch64 or arm64 and bit width is 64.

Install Docker from:
  https://docs.docker.com/engine/install/raspberry-pi-os/
  https://docs.docker.com/compose/install/linux/

After configuring Docker's official repository:
  sudo apt-get update
  sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
    docker-buildx-plugin docker-compose-plugin avahi-daemon
  sudo systemctl enable --now docker avahi-daemon
  sudo usermod -aG docker "$USER"

Sign out and back in, then check:
  docker compose version
  docker run --rm hello-world

Place the project where its systemd units expect it:
  sudo mkdir -p /opt/mail-buddy
  sudo chown "$USER":"$USER" /opt/mail-buddy
  cd /opt/mail-buddy

Copy or clone the repository contents there, then verify:
  test -f compose.yaml && echo "Project root is correct"

Required network access
-----------------------
No public inbound connection is required. Do not create router port forwards.

First setup needs outbound HTTPS for Docker Hub, PyPI package downloads, and
registry.ollama.ai for the pinned model. Gmail authorization and ongoing
polling need outbound HTTPS to accounts.google.com, oauth2.googleapis.com,
gmail.googleapis.com, and www.googleapis.com.

On macOS, TCP/443 stays on host loopback and TCP/8765 is temporary loopback
OAuth only. On the Pi, TCP/443 is allowed only from the configured home subnet;
TCP/22 is needed from the trusted browser computer for the SSH OAuth tunnel.
Mail-Buddy does not use IMAP, SMTP, Pub/Sub, or any hosted-model endpoint.


CONSOLIDATE OTHER MAILBOXES INTO THE CONNECTED GMAIL ACCOUNT
=============================================================
Set forwarding or redirection independently in each source mailbox, with this
Gmail account as the destination. Connect Mail-Buddy only to that destination
account; do not authorize every source account. Mail-Buddy labels received
redirected messages in the destination account using direct top-level labels.

For the first run, use the historical scan and inspect its samples before
approving each category. Afterwards, approved categories sort new redirected
mail automatically. Uncertain or suspicious messages receive Needs Review and
are removed from INBOX.


2. CREATE THE GOOGLE/GMAIL OAUTH CLIENT
=======================================
Do this once for either platform.

1. Open https://console.cloud.google.com/ and create or select a project owned
   by you.

2. Enable "Gmail API".

3. Open "Google Auth Platform" and configure:
   Branding:
     Use a recognizable private name such as Mail-Buddy.
   Audience:
     Use External for a personal Gmail account.
   Data Access:
     Add only:
       https://www.googleapis.com/auth/gmail.modify

   Publishing status:
     Move the personal-use project to "In production". An External project
     left in Testing can issue refresh tokens that expire after seven days.

4. Under Clients create:
     Application type: Desktop app

   Do not create a Web application client. Desktop clients support the
   loopback callback used by this project.

5. Download the OAuth client JSON and keep it private.

Google may show an unverified-app warning for this personal project. Continue
only if the screen identifies your project. A managed Google Workspace
administrator can block gmail.modify; Mail-Buddy cannot bypass that policy.

Official references:
  https://developers.google.com/workspace/gmail/api/quickstart/python
  https://developers.google.com/workspace/gmail/api/auth/scopes
  https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification


3. CREATE .env
==============
From the project root:
  cp .env.example .env

Do not put secrets in it.

For local-only macOS, set:
  MAIL_BUDDY_HOSTNAME=localhost
  MAIL_BUDDY_BIND_ADDRESS=127.0.0.1
  MAIL_BUDDY_SECRETS_DIR=./secrets
  MAIL_BUDDY_OLLAMA_MODEL=llama3.2:3b-instruct-q4_K_M
  MAIL_BUDDY_COLLEGE_DOMAINS=
  TZ=Asia/Kolkata

For the Raspberry Pi, replace the address, hostname, domains, and timezone:
  MAIL_BUDDY_HOSTNAME=mail-buddy.local
  MAIL_BUDDY_BIND_ADDRESS=192.168.1.50
  MAIL_BUDDY_SECRETS_DIR=./secrets
  MAIL_BUDDY_OLLAMA_MODEL=llama3.2:3b-instruct-q4_K_M
  MAIL_BUDDY_COLLEGE_DOMAINS=college.example.edu,placements.college.example.edu
  TZ=Asia/Kolkata

The Pi bind address must be its fixed private IPv4 address, not 0.0.0.0 or
loopback. Find it with:
  hostname -I
  ip route

Reserve it in the router. mail-buddy.local uses mDNS; a router-managed private
DNS name is also valid. College domains are optional, exclude "@", and can be
edited later in the authenticated Settings page.


4. CREATE LOCAL SECRETS
=======================
The cross-platform helper builds the pinned app image, needs no host Python,
and prompts for a dashboard password of at least 12 characters.

On macOS:
  ./scripts/create-secrets.sh

Keep these source files user-owned and private:
  chmod 0700 secrets
  chmod 0600 secrets/encryption_key \
    secrets/session_secret \
    secrets/password_hash

On the Pi, run the same helper as root:
  cd /opt/mail-buddy
  sudo ./scripts/create-secrets.sh

The Pi source directory must be root:root mode 0700 and the files root:root
mode 0600. The helper creates:
  secrets/encryption_key
  secrets/session_secret
  secrets/password_hash

Store the dashboard password in a password manager and keep offline recovery
copies of these files. Replacing encryption_key makes existing encrypted OAuth
tokens and correction-rule values unreadable.

Compose does not give the host files directly to the app. A network-disabled
secret-init service imports all four sources into a private named volume as
UID/GID 10001, directory mode 0700, and file mode 0400.


5. INSTALL THE DOWNLOADED GOOGLE JSON
=====================================
The final filename must be:
  secrets/google_client_secret.json

Do not display its contents.

On macOS, replace the source path:
  install -m 0600 \
    /absolute/path/to/downloaded-oauth-client.json \
    secrets/google_client_secret.json

It remains owned by your macOS user, mode 0600.

For the Pi, first copy it from the browser computer:
  scp /absolute/path/to/downloaded-oauth-client.json \
    pi@192.168.1.50:/tmp/google-client.json

Then on the Pi:
  cd /opt/mail-buddy
  sudo install -o root -g root -m 0600 \
    /tmp/google-client.json \
    secrets/google_client_secret.json
  rm /tmp/google-client.json

Check names, modes, and non-zero sizes without printing secrets.

macOS:
  stat -f '%Sp %Su:%Sg %z %N' secrets/encryption_key \
    secrets/session_secret secrets/password_hash \
    secrets/google_client_secret.json

Expected file mode is -rw-------.

Pi:
  sudo stat -c '%A %U:%G %s %n' secrets/encryption_key \
    secrets/session_secret secrets/password_hash \
    secrets/google_client_secret.json

Expected owner/group is root:root and mode is -rw-------.


6. CONNECT MAIL-BUDDY TO GMAIL
==============================
The exact auth command on both platforms is:
  docker compose --profile auth run --rm --service-ports auth

Do not omit --service-ports. It publishes only:
  host 127.0.0.1:8765 -> auth container 8765

Google's redirect is:
  http://127.0.0.1:8765/

On macOS, confirm port 8765 is free:
  lsof -nP -iTCP:8765 -sTCP:LISTEN

No output means it is free. Run:
  docker compose config --quiet
  docker compose --profile auth run --rm --service-ports auth

Open the printed URL in a browser on that Mac, choose the test account, inspect
the gmail.modify permission, and finish consent.

For the Pi, do not expose port 8765. On the browser computer, open an SSH
tunnel and keep that session open:
  ssh -L 8765:127.0.0.1:8765 pi@192.168.1.50

Inside that SSH session:
  cd /opt/mail-buddy
  docker compose config --quiet
  docker compose --profile auth run --rm --service-ports auth

Open the printed URL on the computer running SSH. Its loopback callback travels
through the tunnel to the Pi.

Success ends with:
  Gmail account connected. Mail-Buddy labels are ready.

Mail-Buddy creates labels and stores the encrypted refresh token in local
SQLite. It never stores the Gmail password.


7. CONFIGURE THE PI FIREWALL AND PREFLIGHT
==========================================
Skip this section on macOS. deployment-preflight.sh is Pi/systemd-only because
it requires Linux networking commands and the Pi firewall configuration.

On the Pi, find the subnet and interface:
  ip route

Apply the included Docker firewall rule, replacing both examples:
  cd /opt/mail-buddy
  sudo ./scripts/configure-firewall.sh 192.168.1.0/24 eth0

Use wlan0 for Wi-Fi. Review the script first if this Pi runs other HTTPS
containers because it limits Docker TCP/443 on that interface.

Persist the same values:
  sudo install -d -m 0755 /etc/mail-buddy
  printf '%s\n' \
    'MAIL_BUDDY_LAN_SUBNET=192.168.1.0/24' \
    'MAIL_BUDDY_LAN_INTERFACE=eth0' \
    | sudo tee /etc/mail-buddy/firewall.env >/dev/null
  sudo chmod 0600 /etc/mail-buddy/firewall.env

Run:
  sudo /opt/mail-buddy/scripts/deployment-preflight.sh /opt/mail-buddy

It validates the fixed address, subnet, interface, root-owned secrets, Compose
configuration, and available storage. Do not run it on macOS.


8. START AND VERIFY
===================
From the project root:
  docker compose config --quiet
  docker compose up --build --detach
  docker compose ps
  docker compose ps -a secret-init model-init
  docker compose logs --tail=100 secret-init app ollama model-init caddy

The first start downloads roughly 2 GB of model layers and verifies the pinned
manifest. A healthy result has:
  - secret-init exited with code 0
  - model-init exited with code 0
  - app, ollama, and caddy running and healthy

Do not bypass a secret import or model-manifest failure.
Verify the app and local SQLite from inside the container:
  docker compose exec -T app python -c \
    "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/readyz').read().decode())"

Expected status is "ready".


9. TRUST CADDY HTTPS AND OPEN THE DASHBOARD
===========================================
After Caddy starts:
  docker compose cp \
    caddy:/data/caddy/pki/authorities/local/root.crt \
    ./mail-buddy-root.crt

This root certificate is public, not a credential.

For the local Mac:
  sudo security add-trusted-cert -d -r trustRoot \
    -k /Library/Keychains/System.keychain \
    ./mail-buddy-root.crt

Open:
  https://localhost/

For the Pi, copy the certificate to each trusted LAN client. On a Mac client:
  scp pi@192.168.1.50:/opt/mail-buddy/mail-buddy-root.crt .
  sudo security add-trusted-cert -d -r trustRoot \
    -k /Library/Keychains/System.keychain \
    ./mail-buddy-root.crt

Open:
  https://mail-buddy.local/

For Debian/Ubuntu clients:
  sudo install -m 0644 mail-buddy-root.crt \
    /usr/local/share/ca-certificates/mail-buddy.crt
  sudo update-ca-certificates

Do not click through a certificate warning. Fix the configured hostname, name
resolution, or trusted root installation.


10. FIRST SAFE MAILBOX RUN
==========================
1. Sign in with the dashboard password.
2. Confirm Gmail connected, model available, queue healthy, and disk healthy.
3. Add real college sender domains under Settings.
4. Start the historical scan under Backfill.
5. Confirm Gmail remains unchanged while decisions are staged.
6. Reveal and inspect samples for each category.
7. Approve only categories whose samples are correct.
8. Correct uncertain messages in Needs Review.
9. Test Activity -> Undo batch with the test account.
10. Connect the real account only after this behaves correctly.

Already archived historical messages receive a category label without returning
to INBOX. Needs Review is also removed from INBOX.


11. COMPLETE .env REFERENCE
===========================
  MAIL_BUDDY_HOSTNAME
    localhost on Mac; private DNS/mDNS hostname on Pi.
  MAIL_BUDDY_BIND_ADDRESS
    127.0.0.1 on Mac; fixed private IPv4 address on Pi.
  MAIL_BUDDY_SECRETS_DIR=./secrets
    Host directory containing four source secret files.
  MAIL_BUDDY_OLLAMA_MODEL=llama3.2:3b-instruct-q4_K_M
    Pinned. Do not change it independently; compose.yaml locks the same model.
  MAIL_BUDDY_OLLAMA_PRIMARY_URL=
    Optional laptop Ollama URL using a literal private or Tailscale IP.
  MAIL_BUDDY_OLLAMA_CONNECT_TIMEOUT_SECONDS=3
    Fast laptop connection timeout before retrying against Pi Ollama.
  MAIL_BUDDY_PERSONALIZATION_ENABLED=true
    Enables scheduled local personalization after enough owner-labeled examples exist.
  MAIL_BUDDY_TRAINING_INTERVAL_DAYS=7
    Run the scheduled personalized-model training check every 1, 3, 7, 14, or 30 days.
  MAIL_BUDDY_TRAINING_HOUR_LOCAL=2
    Start hour (0-23) in TZ for scheduled personalized-model training.
  MAIL_BUDDY_POLL_INTERVAL_SECONDS=120
    Range 30-3600.
  MAIL_BUDDY_BACKFILL_PAGE_SIZE=500
    Range 10-500.
  MAIL_BUDDY_SAMPLE_SIZE=25
    Range 1-100.
  MAIL_BUDDY_MAX_MODEL_INPUT_CHARS=8000
    Range 1000-30000.
  MAIL_BUDDY_OLLAMA_TIMEOUT_SECONDS=120
    Local model request timeout.
  MAIL_BUDDY_WORKER_IDLE_SECONDS=1
    Range 0.1-30.
  MAIL_BUDDY_SESSION_MAX_AGE_SECONDS=43200
    Range 300-604800.
  MAIL_BUDDY_LOGIN_ATTEMPTS=5
    Range 1-20.
  MAIL_BUDDY_LOGIN_WINDOW_SECONDS=300
    Range 30-3600.
  MAIL_BUDDY_COLLEGE_DOMAINS=
    Optional comma-separated domains without "@".
  MAIL_BUDDY_LOG_LEVEL=INFO
    Recommended production value is INFO.
  TZ=Asia/Kolkata
    Replace with the preferred IANA timezone.

Compose supplies /data, /backups, the private Ollama URL, runtime secret paths,
secure cookies, and production mode. Do not override them in normal use. Do
not enable MAIL_BUDDY_DEMO_MODE or MAIL_BUDDY_DISABLE_WORKER for the real
sorter. There is no DATABASE_URL because SQLite is always local.


12. PERSONALIZED LEARNING
=========================
Open Dashboard -> Personal learning. Each Needs Review correction becomes an
encrypted, redacted training example. The Accuracy questions section samples
existing classified mail and asks you for the correct direct label. An answer
both corrects Gmail and becomes ground truth; unresolved Needs Review guesses
are never treated as training truth.

The personalized model is a small local statistical text classifier trained on
the Pi. It is always used as an ensemble companion to the pinned Llama model:
its confidence-scored prediction is sent to Llama as an advisory hint. Agreement
is recorded; confident disagreement is filed under Needs Review. Existing
deterministic security checks still run first.

In Personal learning you can enable or disable automatic training, select a
1, 3, 7, 14, or 30 day interval, select the start hour in TZ, or run companion
training immediately. Each
candidate is tested with deterministic five-fold held-out evaluation. It is
promoted only when minimum example/evaluation thresholds are met, its accuracy
passes the configured floor, and it is not worse than the active version.

Only bounded redacted sender-domain, subject, and Gmail snippet features are
stored, encrypted with the existing encryption key. Full bodies and attachments
remain transient. Disconnecting Gmail deletes examples and trained models.

At 200 suitable examples, an optional Apple Silicon MLX agent can fine-tune
Llama, evaluate candidate and production tags through Ollama, and install the
same checksum-bound Q4_K_M artifact on laptop and Pi before atomic activation.
Follow docs/PERSONAL_LEARNING_AND_MLX_DEPLOYMENT.md for the restricted SSH key,
launchd agent, pinned llama.cpp quantizer, rollback, and privacy instructions.


12. NORMAL OPERATIONS
=====================
Status and redacted logs:
  docker compose ps
  docker compose ps -a secret-init model-init
  docker compose logs --tail=200 app ollama caddy

Pause and resume:
  docker compose stop
  docker compose start

Restart only the app:
  docker compose restart app

Rebuild after a code update:
  docker compose up --build --detach

Remove containers/networks but preserve volumes:
  docker compose down

Never add "-v".

Create an atomic SQLite backup:
  docker compose exec -T app mail-buddy backup

List backup filenames:
  docker compose run --rm --no-deps -T \
    --entrypoint /bin/sh app -c 'ls -1 /backups'

Restore one deliberately selected backup:
  ./scripts/restore-backup.sh \
    mail_buddy-YYYYMMDDTHHMMSSZ.sqlite3

The restore helper validates the backup, stops the app, takes a safety backup,
performs an atomic local SQLite replacement, and restarts the app.

Check SQLite:
  docker compose exec -T app python -c \
    "import sqlite3; c=sqlite3.connect('/data/mail_buddy.sqlite3'); print(c.execute('PRAGMA integrity_check').fetchone()[0])"

Expected output is "ok".

Disconnect Gmail from the dashboard by typing DISCONNECT, or:
  docker compose exec -T app mail-buddy disconnect --yes

Disconnect removes local account metadata and attempts OAuth revocation. It
leaves Gmail labels and message state unchanged.

If source secrets are intentionally replaced, run "docker compose down" then
"docker compose up --build --detach" so secret-init refreshes the runtime
copy. Do not casually rotate encryption_key.


13. PI AUTOMATIC START AND DAILY BACKUP
=======================================
Skip this section on macOS. After the firewall and preflight pass:
  cd /opt/mail-buddy
  sudo install -m 0644 deploy/mail-buddy-firewall.service \
    deploy/mail-buddy.service \
    deploy/mail-buddy-backup.service \
    deploy/mail-buddy-backup.timer \
    /etc/systemd/system/
  sudo systemctl daemon-reload
  sudo systemctl enable --now mail-buddy-firewall.service \
    mail-buddy.service mail-buddy-backup.timer
  systemctl list-timers mail-buddy-backup.timer

mail-buddy.service runs the Pi preflight before every start. The timer creates
an online SQLite backup daily and retains seven backups.
  sudo systemctl status mail-buddy.service
  sudo systemctl restart mail-buddy.service
  sudo systemctl stop mail-buddy.service
  sudo systemctl start mail-buddy.service

On macOS, start Docker Desktop and run:
  docker compose up --build --detach


14. TROUBLESHOOTING
===================
OAuth callback fails
--------------------
Use the exact command:
  docker compose --profile auth run --rm --service-ports auth

The callback is http://127.0.0.1:8765/. On Mac check:
  lsof -nP -iTCP:8765 -sTCP:LISTEN

For Pi OAuth, keep "ssh -L 8765:127.0.0.1:8765 ..." open and use the browser
on that same computer. Never expose port 8765. redirect_uri_mismatch normally
means the JSON is not a Desktop app OAuth client.

Gmail disconnects after seven days
----------------------------------
Move the External OAuth project from Testing to In production, then repeat the
auth flow.

Secret import fails
-------------------
  docker compose ps -a secret-init
  docker compose logs --tail=100 secret-init

Required sources are encryption_key, session_secret, password_hash, and
google_client_secret.json under secrets/. Mac sources are user-owned mode 0600.
Pi source files are root:root mode 0600 and the directory is root:root mode
0700. Never make secret files mode 0644.

Pi preflight fails
------------------
  sudo /opt/mail-buddy/scripts/deployment-preflight.sh /opt/mail-buddy

Read its exact error. The bind address must be assigned to the configured
interface and inside MAIL_BUDDY_LAN_SUBNET. This check is not for macOS.

Model unavailable
-----------------
  docker compose ps -a
  docker compose logs --tail=200 ollama model-init
  docker compose exec -T ollama ollama list

The required model is llama3.2:3b-instruct-q4_K_M. Confirm internet access and
do not bypass manifest verification.

Port 443 is busy
----------------
macOS:
  lsof -nP -iTCP:443 -sTCP:LISTEN

Pi:
  sudo ss -ltnp 'sport = :443'

Stop or reconfigure the conflicting service.

TLS warning
-----------
Use the exact MAIL_BUDDY_HOSTNAME, verify it resolves to the bind address, and
trust Caddy's root certificate. Do not bypass the warning.

Pi is hot or swapping
---------------------
  free -h
  docker stats --no-stream
  vcgencmd measure_temp

Confirm active cooling and stop competing workloads.

Local database location
-----------------------
  docker volume inspect mail-buddy_mail_buddy_data

Do not copy a live SQLite file; use "mail-buddy backup".

For deeper detail, read README.md and SECURITY.md.
